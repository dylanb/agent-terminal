# CLAUDE.md

Agent Terminal — Electron app that hosts coding agents (Claude Code, Codex, …) in a PTY-attached shell session, renders it with xterm.js, tees output into a main-process `@xterm/headless` shadow screen model, and provides a monitor pane that captures output and injects input back into the agent.

`terminal-web-ui-spec.md` is the authoritative spec. Every subsystem implements a numbered section of it; when code and spec disagree, the spec wins — or the spec gets a changelog entry. The exception is IPC wire shapes: channel names and payload types are defined by `src/shared/ipc.ts`, which is authoritative over any prose in §6. Cite spec sections (e.g. §9.3) in code review discussion rather than re-arguing settled design decisions.

## Commands

This repo uses **pnpm** (see `packageManager` in `package.json`). `.npmrc` pins `node-linker=hoisted` so `@electron/rebuild` and electron-builder see a flat `node_modules`; `pnpm.onlyBuiltDependencies` allows node-pty/electron/esbuild to run their install scripts (pnpm v10 blocks build scripts by default).

```
pnpm install        # runs the postinstall electron-rebuild for node-pty automatically
pnpm run rebuild    # electron-rebuild -f -w node-pty — REQUIRED after install or Electron bump
pnpm run dev        # electron-vite dev (renderer HMR)
pnpm run build      # type-check + electron-vite build
pnpm run typecheck  # tsc over src/ and tests/ (tsconfig.tests.json) — vitest strips types without checking them
pnpm test           # vitest, both projects: `node` (tests/unit + tests/integration) and `browser` (tests/browser).
                    # The `pretest` hook runs `typecheck`, then provisions the Chromium the `browser` project needs (a cached no-op after the first run).
./scripts/e2e-podman.sh        # playwright _electron e2e in Podman/Xvfb — the canonical local e2e run (real PTY/display)
./scripts/e2e-podman.sh "<-g>" # filter to matching tests
pnpm run test:e2e   # raw playwright e2e — needs a focusable display; on macOS a bare subprocess launch can't focus, so prefer the Podman harness above
```

**Always run the e2e locally via the Podman harness (`docs/e2e-podman.md`) before claiming a change done — do not defer e2e to CI.**

**Test runs own their GUI windows and processes through verified cleanup on success, failure and interruption, including Terminal wrappers; never close the operator's sessions.** An e2e `afterEach` that owns an Electron app stops it through `tests/e2e/stopApp.ts`, which kills a failed test's possibly wedged app instead of waiting on a `close()` that never returns. → [CODE-STANDARDS.md — Test runs own their GUI windows through cleanup](CODE-STANDARDS.md#test-runs-own-their-gui-windows-through-cleanup).

`node-pty` is a native module compiled against Electron's ABI. If main-process startup fails with a NODE_MODULE_VERSION error, run `pnpm run rebuild`.

## Architecture (orientation only — details in the spec)

- `src/main/` — PTY lifecycle (§5), shadow terminal + quiescence (§8), injection API (§9.3), IPC handlers. node-pty and the shadow live here, never in the renderer. The flow **audit recorder** (§25, `auditRecorder.ts` + `auditPaths.ts`) is observe-only and best-effort: it writes each run's append-only YAML under `~/.agent-terminal/audit/` and never throws into the flow path.
- `src/preload/` — contextBridge exposing the `term` and `monitor` namespaces (§6). No raw `ipcRenderer` in the renderer.
- `src/renderer/` — terminal pane (xterm + app-owned selection, §7) and monitor pane (§9).
- `src/shared/ipc.ts` — the typed IPC contract, assembled from the per-domain modules in `src/shared/ipc/`. It is the single source of truth for channel names, what each channel does (its one-sentence `does`), and payload shapes; main, preload, and renderer all import from `ipc.ts`. A new channel goes in its domain module with its `does` sentence, never as a §6 table row.
- **Semantics two sides must agree on get one definition in `src/shared/`, imported by both — never re-implemented per side.** "Two sides" is any writer/reader pair of one vocabulary — two processes, or a writer and a reader of the same on-disk file — and the predicate deciding what is legal lives in one module. Two copies that "obviously agree today" are the bug. → [CODE-STANDARDS.md § Shared semantics](CODE-STANDARDS.md)
  - Code that writes an asset another component reads computes the destination through that component's own resolver, pinned by `expect(dest).toBe(resolve…(…))`. Against a precedence-aware resolver, the writer targets a named branch of the order (tested **with an override present**); a first-run writer's RED test **deletes the target's root first**. A fixture that pre-creates what the code must handle proves nothing. → [CODE-STANDARDS.md](CODE-STANDARDS.md)

## Test-driven development

- **TDD is mandatory for every code change — RED first, no exceptions.** Write the failing test, run it and observe the failure (the assertion message, not just an exit code), make it pass with the smallest change, then refactor. Bug fixes start with a regression test; features with a test for the acceptance criterion; refactors of behavior-bearing code with a pinning test; API changes by updating the test to the new contract. Tightening an existing test until it would catch the bug counts. Tests written after the implementation are pinning tests, not TDD, and never satisfy this rule; "manual verification" or "tests after" is never acceptable.
  - **Glue and wiring are code.** Button handlers, event subscriptions, IPC wiring, lifecycle hooks: the RED test observes the change's *own* behavior at its own boundary (clicks the button, fires the event). A passing test for a lower-level helper does not license the layer above it.
  - **The sole exemption is code no layer of the stack (unit, integration, Playwright e2e) can observe.** Before writing it, state in writing exactly what cannot be tested and why, and record the gap as an unchecked §12-style item or a tracked GitHub issue (referenced at the site as `// untestable; tracked in #NNN`) — never a code `TODO`. "Hard/slow to test" does not qualify; those get the slow test.
  - Comment/doc-only and formatting edits, and the non-executable files, test code and repo tooling scripts other than red-check that the app-behaviour rule below exempts, are out of scope; anything that can alter behavior (renames, config, build files, dependency bumps) is in, and so is any edit that can break one of that rule's carve-out invariants — if existing tests can't fail when the edit is wrong, write one that can.
- **Evidence of a clean, complete test run is required before declaring any change clean, done, or ready — no exceptions.** Run the full relevant suite — unit, integration, `browser`, and the Playwright e2e **locally in the Podman harness** (`./scripts/e2e-podman.sh`), never deferred to CI — and show the passing tally. A failing or unrunnable suite is never normalized or explained away; only if the Podman harness itself cannot run, stop and escalate to the operator. → [CODE-STANDARDS.md § "Clean"](CODE-STANDARDS.md)
- **Tests MUST exercise observable behavior, NOT implementation — a blocker-level rule.** Assert return values, thrown errors, PTY bytes, IPC payloads on a contract channel, shadow-buffer text through its public read path, visible DOM — never which private method ran, call order/counts, internal data shapes, or anything a behavior-preserving refactor would change. Litmus: could a teammate rewrite the internals from scratch and keep the tests green? Exact bytes are legitimate only where the bytes ARE the contract (`ESC[200~…ESC[201~`, `\r` submit — §9.3). → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- **A test guards app behaviour — never a file nothing executes, the test kit, or a repo tooling script.** A test's subject is production code (`src/`, plus the red-check scripts `scripts/red-check.mjs` and `scripts/red-check-reporter.mjs`) or the running app. Changes to non-executable files (CSS and static markup; docs, the spec, its changelog and the standards files; loop prompts, charters, recipes and skills; CI workflow, build and package metadata; comments and prose in source read as text), to test code itself (`tests/`, `e2e/`, the vitest and Playwright configuration), and to repo tooling scripts under `scripts/` other than red-check get no dedicated tests, and a behavioural test makes no assertion on text, order or structure that the markup or file alone determines.
  - **Carve-out:** a test stays, even when it reads a non-executable file, when the invariant it guards would break the running app, its build or CI enforcement — the `@xterm/xterm` = `@xterm/headless` pin (§8.2), CI workflow checks that lint, build, the vitest suite and the e2e run, a lint rule that enforces a standard being configured and wired into pre-commit and CI, a bundled flow's load-validity (it parses, passes the app's own loader or validator, and every reference it makes resolves — never its wording or configured values), the build placing a shipped asset where the app's own resolver reads it, and a check that enforces a rule a standards file writes down over the source it governs (`tests/browser/colourLiterals.test.ts` for UI-STANDARDS.md §2.2 rule 5).
  - **Configured values:** a behavioural test that depends on a shipped file's configured values (a flow's gate options, a loop's side effects) supplies them as its fixture's own input and never reads them from the shipped file, so changing the shipped configuration cannot break it. `ownPlanLoopGate` in `tests/helpers/e2eExampleConfig.ts` is the shape to copy.
  - **Prompt composers:** a test of a function that returns prompt text asserts only what depends on its input — interpolated values, sections included or omitted by input, and escaping — never fixed wording, and never that a canonical example is well-formed against its predicate. The predicate's and parser's own tests against real inputs stay, including those that use the example as a base input.
  - **Red-check exception:** tests of the red-check run path (the red-check scripts, their app-side callers, and the run they drive through the Podman harness) stay, even where their subject is test code or a script. The exception covers only those two kinds; a fixed-wording or canonical-example assertion inside them still goes.
  - **Timing:** a test passes for correct code at any machine speed or load and can still fail for its defect, so no assertion, wait or timeout encodes a real-time limit.
    - The installed-runtime specs (`tests/e2e/validateFlow*.spec.ts`, `finalizeInstalledAccess.spec.ts`) enforce this and the hermetic rule by lint (the `INSTALLED_RUNTIME_SPEC_RULES` block in `eslint.config.mjs`): no `child_process`, `process.env`, outside Electron launch or fixed sleep; every run goes through `tests/e2e/installedRuntime.ts`.
  - **Locators:** finding an element by its text or accessible name to drive it, or to isolate it for a behavioural assertion, is fine; an assertion whose only purpose is that static copy exists is not.
- **An injection seam exposes a domain concept, NOT the shape of the thing behind it** (`canEnter(dir): boolean`, `now(): number` — not `accessSync`/`statSync`, `Date.now`). Inject the narrowest domain predicate; model a descriptor with mutually-exclusive modes as a discriminated union (`BundleLocation`), never a flat record with dead fields. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- **A platform branch takes the platform as a parameter and returns its decision** (`applyDockIcon(dock, platform, …)`, `buildMenuTemplate(platform, …)`), so a Linux unit test asserts both the macOS and the Linux arm. `process.platform` is read only at the composition root; untested native glue executes the decision and chooses nothing. → [CODE-STANDARDS.md § Platform branches](CODE-STANDARDS.md#platform-branches-take-the-platform-as-a-parameter)
- **Comments state ONLY what the code cannot.** Litmus: could a reader delete the comment, read the code, and recover the fact? If yes, delete it. The default is no comment; only (1) a bare citation of an authority outside this repo (WCAG, CWE, RFC, a wire/third-party format) or (2) a fact near impossible to recover from the code, stating what breaks if violated. Nothing in this repo is cited from code — a bare `§n` only when finding the clause would otherwise mean reading the whole spec. Doc-comments meet the same bar; an asserted invariant is a missing check (enforce it, delete the comment); a parameter's domain goes in a named type; a mechanism comment the change alters is updated or deleted in that change. Code `TODO`/`FIXME` is forbidden (enforced by the `local/no-todo-comments` ESLint rule). → [CODE-STANDARDS.md § Comments](CODE-STANDARDS.md)
- **Expected results are written independently of the code they check.** An oracle fixture never imports the code it grades — only the contract's types — and is listed in `EXPECTED_RESULTS_FIXTURES` (`eslint.config.mjs`), which enforces it. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- **A test stand-in for a controller peer builds messages with `src/shared/controllerProtocol.ts`'s encoder and version constants, never a typed-in version** — `connectScriptedTerminal` for a plain terminal. Only wire-format tests (`WIRE_FORMAT_TESTS`) type versions in. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- **No mocks for the terminal emulator or the PTY.** Integration tests drive the real `@xterm/headless` shadow module with scripted byte streams (it is pure JS and runs under vitest/node). Full-loop behavior (real node-pty, real bash, real renderer) is covered by Playwright `_electron` e2e — never by mocking node-pty. Fake timers/clocks are fine (the quiescence detector takes injectable timers for exactly this); mocking the VT parser is not.
- **An e2e test never boots an Electron it will not use** — a test that launches its own is tagged `@ownapp` and the harness boots nothing for it; the canary at the top of `app.spec.ts` pins this. → [CODE-STANDARDS.md](CODE-STANDARDS.md)

## Tracer-bullet development (mandatory planning requirement)

**Every implementation plan for §24.2 backlog work MUST be decomposed into tracer-bullet slices before any code is written — a plan not sliced this way is incomplete and implementation does not start.** A slice is a thin but *complete* vertical slice — main → `ipc.ts` → preload → renderer → visible UI — doing the smallest real end-to-end thing with real backing, fireable from the UI and RED-first with an `_electron` e2e. ## Code standards

The imperatives below are the enforceable rules; **[CODE-STANDARDS.md](CODE-STANDARDS.md)** carries each linked rule's rationale — cite its section in review rather than re-arguing a settled decision.

- TypeScript, `strict: true`. No `any` in `src/shared/ipc.ts` or `src/shared/ipc/` — the IPC contract is the part TS exists to protect.
- `@xterm/xterm` and `@xterm/headless` are pinned to the same exact version (§8.2) — two parsers at different versions silently corrupt captures. Bump only together.
- Security defaults are non-negotiable: `contextIsolation: true`, `nodeIntegration: false`, paste-breakout `ESC[201~` strip on both injection paths (§7.5, §9.3).
- **Security review defends the trust boundaries the spec names, and escalates any new attack class to the operator.** A finding must cross a spec-drawn boundary (e.g. §27.9.1's human-decided gate) or be ordinary robustness (malformed/missing/unreadable input fails closed). A threat the spec places inside the operator boundary — §27.9.1 treats working agents as trusted operators — is not a finding. An attack class the spec does not settle is escalated as a `needs a human` decision, never silently hardened against or dismissed: adding a boundary is a spec decision.
- Untrusted data crossing a process/shell/OS boundary travels as a structured value (env var, `argv` element, quoted literal), never concatenated into a string the far side parses (CWE-78). → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- Any value placed into shell text is quoted through `src/shared/shellQuote.ts`, never hand-rolled (CWE-78). → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- Any path derived from repo content is confined through `src/main/confinedPath.ts` before it is walked, opened, or written (CWE-22/59/367). `resolveJail` for a jail inside untrusted content, `resolveOwnedDirJail` for a root in the user's own space — getting that backwards is the bug. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- A file whose path is derived from repo content is read through `src/main/boundedRead.ts` (`readBoundedNoFollow` with a named `MAX_…_BYTES` limit), never `readFileSync` or a `stat`-then-read, so a named pipe, a swapped file or an oversized one is refused rather than blocking or read whole (CWE-367/400). → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- A caught value's "which errno?" and "what do I tell the user?" are answered by `src/main/errno.ts` (`isErrno` against a closed `ErrnoCode` union, `errMsg`), never inline. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- A tree-walk whose emptiness would be a silent DATA problem uses `src/main/dirEntries.ts` — absent yields `[]`, unreadable throws. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- A closed set of values is one `as const` list with its type derived from it; membership is checked with `isOneOf` (`src/shared/oneOf.ts`, enforced by lint), and every place that acts on each member is bound to the list at compile time — a `switch` with a `never` default or a `Readonly<Record<T, …>>` — so a new member fails `pnpm typecheck` wherever it is unhandled. → [CODE-STANDARDS.md § Closed lists](CODE-STANDARDS.md#closed-lists--one-list-isoneof-for-membership-the-compiler-for-every-use)
- An untrusted persisted value feeding a safety limit is validated field-locally at the read boundary and relationally at the use site, and its fallback fails toward the limit still firing (CWE-20/770). → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- A prompt that instructs an agent to produce an artifact a predicate gates on shares one descriptor with that predicate, embeds that descriptor's canonical example, and has the agent produce JSON it checks with that same predicate before signalling done — never a hand-written Markdown grammar. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- No production code modifies the user's `.gitignore`, ever (§19.1/§25); persistence tests assert the write creates none and leaves an existing one byte-for-byte unchanged. Only an explicit, user-invoked install action is exempt. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- App-owned state with an independent set/clear lifecycle lives in its **own file**, disjoint from any wholesale-written document (`polish.yaml`/`armed-interrupt.yaml` vs `run-state.yaml`, §27). → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- Bracketed-paste mode is read live at injection time (renderer `term.paste()`; main `shadow.modes.bracketedPasteMode`) — never cached, never decided by us (§9.3).
- Renderer UI follows **[`UI-STANDARDS.md`](UI-STANDARDS.md)** — atomic tiers, per-component tests (organisms also get e2e + a relocation test), typed `createX(host, deps)` factories, host-subtree only, services injected, `src/renderer/src/tokens.css` theming.
- Every renderer control runs its press through `src/renderer/src/pressable.ts`, and an action returns the promise for the work it starts, so neither it nor a related control can start again while that work is pending (enforced by lint). → [UI-STANDARDS.md §1.4](UI-STANDARDS.md)
- The monitor pane talks only to `window.monitor.*` (§9.1) — never imports terminal/selection modules or touches renderer xterm state, which keeps it relocatable to a separate process.
- Timing values are named and configurable where the spec says so: `SUBMIT_DELAY_MS` via `APP_SUBMIT_DELAY_MS`, `QUIET_MS`, the 80 ms resize/settle debounces (§7.1, §8.2, §9.3). No new magic-number sleeps.
- Every IPC payload carries `sessionId` (§6), and the identity of the resource it acts on; the receiver never re-derives that target from ambient state — a data-loss defect for destructive or outward-facing actions. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- Published state snapshots define ownership and isolate consumers, nested values included; tests verify isolation through observable behavior. → [CODE-STANDARDS.md § Published snapshots](CODE-STANDARDS.md#published-snapshots-have-explicit-ownership-and-isolate-consumers)
- A best-effort or cosmetic side effect must never abort the critical path it sits on; wrap it, and coerce every caught value as `unknown` (`e instanceof Error ? e.message : String(e)`). → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- Never silently swallow an error whose consequence is a state the user cannot recover from through the UI — surface it and leave a retry/back-out path. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- Never allow an unrecoverable state: every operation rolls back to the prior good state or forward to one with a visible next action. When unsure whether a path has a UI route out, ask the operator before building it. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- The policy authorizing a destructive operation is checked at the operation (not at the prompt that precedes it) and hard-fails before any prompt is raised. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- Every §25 run-log entry is true: written only when that outcome happened, never one entry for two outcomes. When a yes/no can't tell outcomes apart, return a value naming each, and RED-test both directions. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- One theme per PR — a second theme wants a second PR, or a per-theme review checkpoint when they must land together. → [CODE-STANDARDS.md](CODE-STANDARDS.md)
- Fixing churn or dev friction you hit while doing a PR's work is REQUIRED in that same PR — it is not a second theme. The boundary is the source of the discovery, not the file it touches. → [CODE-STANDARDS.md](CODE-STANDARDS.md)

## Ticket standards (agent-loop ready)

Tickets are GitHub issues. A ticket is **agent-loop-ready** only when a human applies the **`agent-loop/ready`** label — **do not add it yourself**; it means a human has vetted the ticket against the full authoring contract in **[TICKET-STANDARDS.md](TICKET-STANDARDS.md)**.
