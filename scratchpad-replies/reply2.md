Fixed in 78f51a4. `requireTestGlobs` now rejects, at parse time, any glob using syntax `globMatch` treats as literal — braces `{}`, char-classes `[]`, and a `**` that isn't a whole segment — so a mis-specified glob is a loud `malformed` load failure instead of silently matching nothing and letting the §28.5.1 frozen check read as "no test changed" (the fail-away). The supported grammar (`*`, `?`, whole-segment `**`) is unchanged, and `select_template` is untouched since it isn't a glob. RED test in `tests/unit/loopCapabilities.test.ts`.
